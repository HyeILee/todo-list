# 개인 사이트 운영 연결

개인용 To-do List의 GitHub–Vercel 자동배포와 로그인·백업 확인 절차입니다.
기관 내부정보를 취급하는 별도 운영 절차는 기존 배포 문서의 적용 범위를 따릅니다.

## 자동배포

- 저장소: `HyeILee/todo-list`
- 기존 Vercel 프로젝트: `dugyeon-schedule`
- 운영 도메인: https://todo-day-log.vercel.app/
- 운영 브랜치: `main`
- GitHub Vercel 앱의 저장소 접근은 `Only select repositories`에서 이 저장소를 포함합니다.
- 프로젝트의 Git 설정은 위 저장소에 연결되어 있어야 합니다.
- Production 환경의 Branch Tracking이 `main`인지 확인합니다.

`main`의 새 커밋이 Vercel의 Production 배포로 자동 생성되고, 해당 커밋의 빌드가
`Ready`가 된 뒤 운영 도메인이 그 배포를 가리키는지 확인합니다.
수동 재배포 성공만으로 Git 자동배포 검증을 대신하지 않습니다.
재연결 확인에는 애플리케이션 실행 코드를 바꾸지 않는 문서 변경을 사용할 수 있습니다.

운영 데이터베이스 연결·기존 사용자·도메인을 바꾸거나 새 프로젝트를 만들 필요는 없습니다.
환경 변수 변경은 새 배포부터 적용되므로, 로그인 설정 변경 후에는 새 배포를 확인합니다.

## Google 로그인 설정

기존 개인 계정에 Google 계정을 명시적으로 연결하는 방식입니다.
이메일 주소가 같다는 이유만으로 계정을 자동 연결하거나 새 사용자를 만들지 않습니다.

Google OAuth 클라이언트의 애플리케이션 유형은 웹 애플리케이션이며,
승인된 리디렉션 URI는 다음과 같습니다.

```text
https://todo-day-log.vercel.app/accounts/google/callback/
```

현재 구현의 요청 범위는 `openid email`입니다.
메일함·드라이브 접근 범위를 추가하지 않습니다.

Vercel Production에 필요한 환경 변수:

- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `GOOGLE_LOGIN_ENABLED=true`

클라이언트 비밀 값은 보안 입력 화면에서 설정하며 저장소·문서·채팅에 넣지 않습니다.
설정이 모두 준비된 후 새 운영 배포에서 로그인 화면과 계정 연결을 확인합니다.

## 패스키 및 계정 연결 확인

1. 기존 사이트 계정으로 로그인합니다.
2. 설정의 로그인 추가 인증에서 사용자의 실제 기기·브라우저에 패스키를 등록합니다.
3. 추가 인증 활성화와 패스키 검증을 확인합니다.
4. 현재 비밀번호와 패스키로 본인 확인 후 Google 계정을 연결합니다.
5. 별도 브라우저 세션에서 Google 로그인 및 추가 인증 흐름을 확인합니다.

복구 코드는 본인이 보관합니다. 원격 작업용 브라우저에 등록된 패스키를
사용자 본인 기기의 패스키 등록으로 간주하지 않습니다.

## 실제 백업 다운로드 확인

1. 운영 사이트의 실제 계정으로 로그인해 백업 화면을 엽니다.
2. 전체 데이터 ZIP을 내려받고 파일 수신 완료를 확인합니다.
3. ZIP 손상 여부와 필요한 파일 구성을 확인합니다.
4. 사진은 사진 백업 ZIP도 별도로 내려받아 확인합니다.
5. 복원 시험이 필요하면 운영 데이터 대신 격리된 시험 환경에서 진행합니다.

실제 백업의 일정·메모·사진 내용을 공개 저장소, 시연 화면 또는 공유 자료에 넣지 않습니다.
