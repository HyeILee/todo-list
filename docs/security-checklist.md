# 보안 체크리스트

## 승인 전

- [ ] 실제 내부정보 기록/원격 접속/개인 휴대폰 접근에 대한 기관 승인 확보
- [ ] 서버 및 백업 위치, 보존·파기, 접근 로그와 사고 보고 절차 확인
- [ ] 승인 전 더미 또는 비민감 데이터만 사용하고 로컬 loopback 유지

## 애플리케이션과 배포

- [ ] `DEBUG=false`, 강한 비밀 키 비밀 저장소 관리, 명시적 허용 호스트
- [ ] HTTPS 프록시, CSRF trusted origin, Secure/HttpOnly/SameSite 쿠키
- [ ] CSP, `X-Content-Type-Options`, `Referrer-Policy`, frame 제한 확인
- [ ] CSRF 유지, 사용자 HTML 렌더링 금지, 로그인 시도 제한 확인
- [ ] SQLite/백업/로그가 정적 디렉터리 밖이며 단일 쓰기 서버인지 확인
- [ ] 기관 승인 저장장치 암호화 및 백업 접근 제어 확인

## 데이터와 파일

- [ ] 수동 백업 다운로드는 로그인과 재인증 필요
- [ ] Excel/CSV/ZIP은 평문임을 인지하고 다운로드 폴더 및 전송본 관리
- [ ] 업무 데이터와 개인 기록 내보내기 분리, 로그/오류 응답에 본문 미포함
- [ ] 복원 전 manifest 해시/버전/SQLite 무결성 검증 및 사전 백업 확인
- [ ] 손상 ZIP 테스트에서 현재 DB가 유지되는지 회귀 테스트

## 잔여 운영 결정

- 자동 로그인 실패 지연·차단은 Django Axes 설정을 사용합니다. 기관 정책에 맞는 차단 임계값/해제 절차를 확인합니다.
- 자동 백업 암호화는 자체 구현하지 않습니다. 저장장치 암호화와 기관 표준을 확인합니다.
- 이 저장소만으로 실제 기관 승인을 증명하지 않으며, 승인 문서와 운영 프록시 정책은 담당자가 확보해야 합니다.
