# 백업과 복원

## 백업 알림

기본 7일 주기로 앱을 열 때 백업을 권유합니다. 14일·30일 주기도 선택할 수 있고, 팝업은 하루 동안 미룰 수 있습니다. 알림 주기·미루기·보관 완료일은 계정에 저장되어 PC와 휴대폰에서 함께 사용됩니다. 최초 보관 완료 기록이 없으면 첫 백업을 안내합니다.

ZIP 생성만으로 보관 완료일을 변경하지 않습니다. 사용자가 파일을 실제로 내려받아 보관했다고 확인한 뒤 다음 권장일을 계산합니다. 사진이 있으면 사진 ZIP도 보관했는지 확인합니다. 앱을 닫은 동안 별도 푸시 알림을 보내거나 파일을 자동으로 생성하지 않습니다.

## 수동 백업

설정 → 백업 및 복원에서 현재 비밀번호를 다시 입력해 ZIP을 받습니다. SQLite에서는 온라인 DB 스냅샷과 Excel/CSV를, PostgreSQL에서는 카테고리·일정·상태 이력·일기·사진 메타데이터와 Excel/CSV를 담습니다. PostgreSQL ZIP에는 계정·세션·로그인 기록이 포함되지 않습니다. manifest는 파일별 SHA-256·스키마 버전·생성 시각·건수를 기록합니다.

사진 원본은 일정·기록 ZIP에 들어 있지 않습니다. 사진첩의 **ZIP으로 전체 저장**으로 별도 보관합니다. 사진 메타데이터 복원만으로 저장소에서 삭제된 사진 원본을 복구할 수는 없습니다.

ZIP은 평문 데이터이므로 본인이 관리하는 적절한 위치에 보관합니다. 자체 ZIP 암호화는 추가하지 않았습니다.

## 자동 백업

애플리케이션 자동 백업은 기본적으로 꺼져 있습니다. 기존 SQLite 자동 백업 코드는 관리자가 명시적으로 `AUTOMATIC_DATABASE_BACKUPS=True`로 설정한 경우에만 동작합니다. PostgreSQL에서는 앱의 로컬 파일 자동 백업을 사용하지 않습니다. DB 제공자의 별도 복구 기능은 앱 알림과 독립적입니다.

## 복원

SQLite 웹 복원에는 로그인·비밀번호 재입력·명시적 확인이 필요합니다. ZIP 목록·크기·해시·버전·SQLite 무결성·건수를 검증하고, 복원 전 안전 백업을 만든 다음 임시 DB를 교체합니다. 직전 0006 스키마의 SQLite 백업은 임시 사본에 알림 테이블을 추가한 뒤 교체합니다. 기존 일정·일기·사진을 수정하는 마이그레이션은 없습니다.

PostgreSQL 일정·기록 복원은 쓰기를 중단한 관리 환경에서 `restore_data_backup` 명령으로 수행합니다. 계정과 백업 알림 설정을 보존합니다. 직전 `dugyeon-data-v1` 일정 ZIP도 검증하여 복원할 수 있으며, 사진 정보가 없는 과거 ZIP은 현재 사진 정보를 삭제하지 않습니다. 다른 스키마의 백업은 자동 호환으로 간주하지 않습니다.

복원은 앱 쓰기를 중단한 상태에서 진행합니다. 손상되거나 호환되지 않는 파일은 현재 데이터를 바꾸지 않습니다.
